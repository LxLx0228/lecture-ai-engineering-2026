# 発展課題：講座用語集のSFTと検索の比較

`data/glossary.json` の58語を、講座の `scripts/make_sft_dataset.py` を変更せず実行して116件の `messages` 形式のQ&Aにした。生成処理は標準ライブラリだけなので、手元のPythonで実行した。LoRA学習・推論はColabの無料T4で実行した。

## ファイル

- [再実行用ノートブック](../../../notebooks/lora_glossary_advanced.ipynb)：依存導入・データ展開・実験実行。APIキー不要。
- `prepare_data.py`：講座スクリプトを呼び、データと評価問題を保存する。
- `evaluation_cases.py`：実行前に固定した評価42問と概念語群。
- `experiment_common.py`：概念の代理採点と、質問中の名前・別名を照合する検索。
- `run_experiment.py`：学習前評価、LoRA学習、学習後評価、検索比較、結果保存。
- `verify_results.py`：保存した出力の再採点と整合性確認。
- `data/`：用語集スナップショット、元の生成116件、train/valid、評価問題、ハッシュ。
- `results/`：20エポック追試の指標・全出力・学習ログ・入力ファイルのハッシュ。
- `runs/epochs05/` と `runs/epochs20/`：それぞれの実行時ソース・入力・結果のスナップショット。後から変更した検証コードと区別する。

## 分割と比較

各語の1つ目の質問テンプレート58件をtrain、2つ目58件をvalidにした。各recordには評価時と同じsystem文を先頭に加え、元のuser/assistantの対は保持した。58語の定義はtrainとvalidで共有され、未知の用語への汎化を測る分割ではない。評価は12語について用語名・別名・説明的な言い換えを各1問と、未掲載語6問の計42問。質問文字列はtrain/valid/test間で重複しない。

学習前後のモデルには、同じsystem文と質問だけを渡す。用語集の定義、用語の一覧、検索結果、正解概念語群は渡さない。検索方式は質問文だけから名前・別名・idを照合し、最長一致の用語の定義をそのまま返す。正解idによる検索語の置換やLLMによる書き換えはしない。これは生成モデルを使わない名前検索であり、埋め込み検索やRAG全体の性能を代表するものではない。

学習前後は同じモデルrevision・プロンプト・EOS・最大生成長256・貪欲生成。LoRAのrank16、alpha32、lr2e-4、バッチ4×累積2、float32を維持した。最初は5エポック・40ステップで実行し、定義を十分に再現できず保留判断も悪化した。初回の原文と失敗を保存した上で、セッションを再起動し、講義の標準と同じ20エポック・160ステップを追加で試した。

追試では40ステップごとにvalid損失を測り、最小のチェックポイントを読み込む。初回の42問の結果を見て学習回数を増やす判断をしたので、同じ42問での比較は探索的な結果として扱う。追試前に、初回の評価対象ではない6語と新しい未掲載6問から別の12問を固定した。訓練・検証データと元42問、その採点規則は変更しない。追加12問も学習データやチェックポイント選択には使わない。

エポック数を増やすとcosine減衰の総ステップ数も40から160に延びる。また追試では検証損失による選択も追加したので、5→20エポックの比較は厳密な一因子の因果実験とは扱わない。

追試の基盤モデルの42問は、同一revision・同一生成条件の初回出力を変更せず再利用し、未学習モデルから2問を再生成して一致を確認した。追加12問の学習前出力は新しく生成する。学習後にもadapterを無効にした2問の出力一致を確認した。

## 指標の読み方

既掲載語36問は、実行前に用意した複数の概念語群をすべて満たすかを採点する。これは意味の正しさの代理指標で、部分文字列の一致だけでは余分な誤りや否定を検出しきれないため、生成原文も確認する。用語集と一字一句同じ回答の割合は別に記録する。

未掲載語6問は、講座用語集の範囲外であることを認め、確認を求めたかを測る。実在する一般用語3つと、作った名前3つを含む。一般用語への説明が正しい場合もあるため、範囲外の応答をすべて「虚偽」とは呼ばない。訓練データには保留回答の教師例を追加していない。用語集の所属範囲も推論時に一覧としては渡さないため、保留判断にはこの条件の制約がある。

## 再現と検証

データを作り直す場合（リポジトリのルートから）：

```sh
python3 lectures/02/advanced/prepare_data.py
```

Colabにノートブックをアップロードし、T4 GPUで上から実行する。初回の基盤モデル出力は同梱し、同一の基盤モデルであることを再生成で確かめてから再利用する。追試の結果は `/content/aie_day2_advanced/results20/` に保存される。実測JSONを保存してからランタイムを接続解除して削除する。保存した両実験の再採点はモデル不要：

```sh
python3 lectures/02/advanced/verify_results.py
```

データ設計・コード変更・Colab操作・考察の草稿にはCodexを使用した。実行結果は本人のColabランタイムから回収し、講師の参考出力とは混ぜない。


## 実測と計測修正

追試は20エポックを完了し、valid loss最小のcheckpoint-120（15エポック）を選択した。[詳細レポート](REPORT.md)と[全回答比較](comparison.md)を参照。初回の失敗も保存している。

実行時の長さ確認は `len(BatchEncoding)` により辞書の項目数を測っていた。元の記録を残し、学習後に `input_ids` の長さを再計測した `token_lengths_verified.json` を両試行に追加した。最大176は512以内で、trainトークン合計×エポック数もTrainer記録と一致した。現在の `run_experiment.py` とノートブックには長さ計測の修正を反映した。`runs/` の実行時ソースは変更せず保存している。
