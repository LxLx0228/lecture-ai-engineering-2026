# 第3回 解答

比較には、Ollama 上で動く Qwen2.5 3B を使った。比較時は両フレームワークで同じモデルと質問を使い、温度を 0 に設定した。コードの既定モデルは講座の Gemini 設定を使う。

## 演習

- 「AIE2026の講座の宿題にある『3レベル』とは何ですか？」に対し、素の LLM は内訳を答えられず、講座の提供元も誤った。エージェントも最初の試行では検索を呼ばず、用語集に載っていないと回答した。検索語を明示した再試行では、用語集に沿って「基礎・実装・発展のどれか1つ」と答えた。検索するよう指示しても、実際にツールを呼んだかはトレースで確認する必要がある。
- 検索語を明示した再試行で `search_glossary({"query":"3レベル"})` を1回呼んだ。LLM の `requests` は最初の試行で1回、再試行で2回だった。
- 追加したツールは `make_quiz(lecture)`。確認問題を頼まれたときに使うこと、講義回を整数で受け取り、用語集から問題と答えの組を返すことを docstring に記述した。該当する用語がなければ、その理由を返す。
- 「第2回の内容から確認問題を1問出して」では `make_quiz({"lecture":2})` を1回呼び、`requests` は2回だった。ツールが返した「QLoRAの意味は？」を出題し、モデルは選択肢を補った。正解の提示はなかった。

## 宿題

### 基礎

「LoRAとQLoRAの違いは？」を同じツール構成で比較した。`INSTRUCTIONS` の末尾に関する指示1行を、関係する講義回を示す指示から、理解を確かめる質問を1問添える指示に変えた。

変更前後とも `search_glossary({"query":"LoRA"})` が1回呼ばれ、LLM の `requests` は2回だった。変更前は本文で第2回演習に言及し、要点の説明で終わった。変更後は「理解できましたか？」を末尾に添えた。検索回数や引数は同じだったが、回答の締め方が変わった。具体的な知識を問う確認問題にするには、質問の条件をもう少し具体化する余地がある。

### 実装

`save_learning_log(summary)` を追加し、`requires_approval=True` で登録した。保存要求を受けたら CLI に対象の本文を表示し、呼び出しごとの選択と会話履歴を渡して再開する。承認された記録は `learning_log/` に新規の Markdown ファイルとして保存する。空入力は拒否扱いとする。

Pydantic AI のテスト用モデルで、確認時点では保存先がまだ作られていないこと、承認すると本文を含むファイルが1件できること、拒否すると0件であることを確認した。テストは14件すべて通過した。

### 発展（a）Google ADK

Pydantic AI 版と同じ `INSTRUCTIONS`、`search_glossary`、`get_lecture_summary`、`make_quiz` を使って ADK 版を作った。Pydantic AI は `tool_plain` でツールを登録し、実行時にモデルを渡す。ADK は `Agent` を組み立てるときに、モデルと関数のリストを `model` と `tools` に渡す。

ローカルのモデル接続に差し替えて `adk run` で「LoRAとQLoRAの違いは？」を実行した。ADK の実行イベントでも `search_glossary({"query":"LoRA"})` が1回呼ばれた。どちらも、LoRA の低ランク行列による学習と、QLoRA が重みを量子化してメモリを節約する点を説明した。Pydantic AI 版の末尾は「理解できましたか？」で、ADK 版は「LoRAとQLoRAの違いを説明できますか？」だった。入力の組み立てやツール結果の渡し方にも差があり、今回の1問で文面の違いの原因を特定することはできない。

講座設定で起動するコマンドは `PYTHONPATH=. uv run --frozen --with google-adk adk run adk_agent/glossary_agent`。Gemini APIでの応答は未確認。
