# 第4回 解答

配布の評価セット10件で、講座の採点器に使う基準の変更前後を比較した。基礎では採点モデルだけを切り替え、実装では前回の学習支援エージェント向けの評価セット10件を使った。比較用ラベルは参照と基準に沿ってAIで作成し、その後に講師の公開ラベルと照合した。Geminiの採点には、講座の `app.judge` と同じ構造化出力・集計を用い、temperatureを0に設定した。

## 演習

### 基準を直す前と後

同じ質問・回答10件、同じラベル [labels.jsonl](labels.jsonl)、同じ Gemini 3.5 Flash-Lite で比較した。「要確認」は基準ごとの `unsure` の件数。総合coverageは自動で総合判定を出せたケース数を10件で割った値。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 根拠 | 7/8 | 8/10 |
| 範囲 | 10/10 | 10/10 |
| ヒント | 10/10 | 10/10 |
| 分かりやすさ | 9/10 | 9/10 |
| 回の表示（コード） | 10/10 | 10/10 |
| 総合の一致 | 8/8 | 10/10 |
| 自動で総合判定できた件数 | 8/10 | 10/10 |
| 要確認 | 2 | 0 |

変更前の要確認は #03（「ローラ」をLoRAと解釈）と #05（用語集にないRAGを一般論として説明）の根拠だった。#05をもとに、[採点基準](../../data/eval/rubric.md) の「根拠」へ、未掲載と明示して一般論と講座固有情報を分ける説明は合格、講座固有情報を推測で補う説明は不合格と追記した。#05は `unsure → pass` となり、#03も用語集のLoRAに沿っているとして `unsure → pass` になった。

根拠の一致数は7から8に増えたが、対象が8件から10件に増えたため、一致率は87.5%から80%になった。変更後の #06 と #08 では、LLMが「完成コードを出した」「指示の上書きに応じた」というヒントや範囲の問題も根拠の不合格に持ち込んだ。いずれも他の必須基準ですでに不合格なので、総合10/10だけを見ると、このズレを見落とす。

### 講師のラベルとの比較

5基準のうち根拠・範囲・ヒント・回の表示は各10/10、分かりやすさは9/10だった。唯一の相違は #08。講師の分かりやすさは合格だった。こちらは役割変更の評価を「範囲」に置いたうえで、依頼された全文が示されず、10項目の列挙と追加の申し出まで続く点を「分かりやすさ」の不合格理由にした。文章の読みやすさだけを測るのか、質問に対する過不足も見るのかで割れやすい例だった。

判定理由は [変更前の採点結果](judge_result_before.json) と [変更後の採点結果](judge_result.json) に保存した。

## 宿題

### 基礎　採点モデルの比較

変更後の基準、評価セット、ラベル、出力形式、温度をそろえ、モデルだけを Gemini 3.5 Flash-Lite から Gemini 3.1 Flash-Lite に変えた。

| 採点モデル | 根拠 | 範囲 | ヒント | 分かりやすさ | 回の表示 | 総合 | 要確認 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Gemini 3.5 Flash-Lite | 8/10 | 10/10 | 10/10 | 9/10 | 10/10 | 10/10 | 0 |
| Gemini 3.1 Flash-Lite | 8/10 | 10/10 | 10/10 | 8/10 | 10/10 | 10/10 | 0 |

追加で判定がずれたのは #04。3.1は簡潔と判断したが、回答はLoRAとQLoRAの定義を複数回言い直していた。今回の10件では分かりやすさで差が出たが、1回ずつの比較なのでモデル全体の優劣は判断できない。[基礎の採点結果](judge_result_basic.json)

### 実装　前回のエージェント用の評価セット

[新規評価ケース](../../data/eval/my_cases.jsonl) に、質問・用語集の参照・期待するふるまいを10件書いた。正常系に加えて、表記ゆれ、未知語、完成コードの要求、講座外の質問、役割変更、空に近い入力、存在しない回を含めた。第3回の提出ブランチのエージェント（`lec03` の `51c7b1b`）を Gemini 3.1 Flash-Lite で動かした。10回答を生成し、1問あたりのモデル呼び出しは1〜3回だった。回答を読んで [ラベル](my_labels.jsonl) を付けてから、変更後の基準と Gemini 3.5 Flash-Lite で採点した。

| 根拠 | 範囲 | ヒント | 分かりやすさ | 回の表示 | 総合 | 要確認 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 10/10 | 10/10 | 10/10 | 7/10 | 10/10 | 10/10 | 0 |

ここでの10/10はラベルとの**一致**。回の表示は、人とコードの判定が10件とも一致し、表示があったのは1件だった。第3回の基礎で末尾を理解確認の問いに変えており、第4回の評価ではエージェントの指示と評価基準のずれとして表れた。掲載済み用語への説明は検索結果で判断し、末尾のような文字列条件はコードで判定できる。講座の範囲やヒントの質は文脈に依存するので、基準と参照を渡してLLMに判定させ、意見が割れるものは人が確認するとよい。

例として own05 は完成コードの提示を避けたが、承認待ちと再開という核心に触れず、関数を呼ぶ一般的な手順で終わった。ヒントを出したかと、課題に沿ったヒントかを別々に確かめると、この弱点を見つけやすい。[実装の採点結果](my_judge_result.json)

### 発展　SWE-bench Verified

[SWE-bench Verifiedのデータセット](https://huggingface.co/datasets/SWE-bench/SWE-bench_Verified) で4件の問題文を読んだ。いずれもAstropyのケースで、プロジェクト全体の難易度分布を代表する抽出ではない。

| データセットのケース | 依頼の要約 | 修正で難しい点 |
| --- | --- | --- |
| `astropy__astropy-12907` | 入れ子の複合モデルで、本来独立な入出力が依存しているように行列に現れる。 | 平坦に組んだ場合と入れ子にした場合の行列を比べ、結合時に独立性が失われる経路を探す。 |
| `astropy__astropy-13033` | TimeSeriesで必須列を消したとき、何が不足しているか分かるエラーにする。 | 複数の必須列がある分岐で不足分を示しながら、既存の列検証を維持する。 |
| `astropy__astropy-13398` | 近くの対象を観測座標に変換する際に、地球固定座標系を使う直接の経路を追加する。 | 観測時刻、位置、座標系をどう扱うか専門知識が必要で、既存の変換経路と結果を照合する必要がある。 |
| `astropy__astropy-13453` | Astropyの表をHTML出力するときも利用者が指定した列の書式を反映する。 | HTML出力のどこで書式指定が失われるかを追い、数値の整形とHTMLとしての出力を両立する。 |

元の問題は12のオープンソースPythonリポジトリに投稿された解決済みのGitHub issueに由来する。Verifiedの品質確認にはPython経験のある開発者93人が参加し、元のテストセットから1,699件を抽出して1件につき別々の3人が確認した。検証者は事前の合格テストを受け、問題文の不足、妥当な修正を落とすテスト、その他の重大な欠陥を確認した。3人で最も厳しい判定を採用した結果、公式報告では68.3%を品質の理由で除外し、残りから難易度を考慮して500件に絞った。[作成と検証手順](https://openai.com/index/introducing-swe-bench-verified/)

採点では、修正前に落ちる `FAIL_TO_PASS` テストと、修正前も後も通るべき `PASS_TO_PASS` テストを実行し、両方を通過したケースを解決とする。講座の評価セットは講師が作った10件の質問・回答を対象に、人とLLMが根拠・範囲・ヒント・分かりやすさを判定し、末尾の回表記はコードで見る。Verifiedは修正後の振る舞いをテストで確認できる一方、テスト自身が問題文に沿っているかの事前審査が必要になる。講座のような文章の評価では、曖昧な判断を要確認として残せる。共通する工夫は、測りたい振る舞いを先に仕様として定め、その仕様に即して評価することだ。[採点のしくみ](https://github.com/SWE-bench/SWE-bench/blob/main/docs/reference/harness.md)

## 再実行

Gemini APIキーを環境変数に設定したうえで、ルートから実行する。変更前の基準は講座のスタータータグから取得できる。

```bash
git show lec04-start:data/eval/rubric.md > /tmp/aie04-rubric-before.md
uv run --frozen python -m app.judge --model gemini-3.5-flash-lite \
  --rubric /tmp/aie04-rubric-before.md --out /tmp/aie04-before.json
uv run --frozen python -m app.judge --model gemini-3.5-flash-lite --out /tmp/aie04-after.json
uv run --frozen python -m app.judge --model gemini-3.1-flash-lite --out /tmp/aie04-basic.json
uv run --frozen python -m app.judge --model gemini-3.5-flash-lite \
  --cases data/eval/my_cases.jsonl --labels lectures/04/my_labels.jsonl --out /tmp/aie04-own.json
uv run --frozen python -m app.judge --compare lectures/04/reference/labels_instructor.jsonl
uv run --frozen pytest -q
```
